## この章でやること

手動作成した Azure インフラを題材に、Copilot Chat を使って Bicep のたたき台を作成します。実際のデプロイは行わず、生成された Bicep を読み解きながら IaC 化の考え方を学びます。

目安時間: 30分

> **重要**  
> この章では Bicep の build による構文確認だけを行います。`az deployment group create` などのデプロイコマンドは実行しません。

## 手順

### Bicep 化する範囲を決める

1. 前の章で作成したリソース一覧または Mermaid 図を開きます。
1. すべてを一度に Bicep 化しようとせず、まずは小さな範囲を決めます。
    - VNet と Subnet
    - NSG
    - Linux VM と NIC
    - NAT Gateway の関連付け
1. Copilot Chat を Plan に切り替え、Bicep 化の方針を相談します。
    - この Azure 構成を Bicep に起こす場合、どのリソースから書き始めるのが良いですか？
    - 既存リソースとして参照するものと、新規作成するものを分けてください。
    - 初心者向けに、最小構成の Bicep から始めたいです。
1. Copilot が提示した計画について、次を確認します。
    - 作成・変更する予定のファイル
    - 新規作成するAzureリソースと、`existing` で参照するリソース
    - シークレットの扱い
    - 実行予定の検証コマンド
    - `az deployment group create` が含まれていないこと
1. 不明点や不要な変更があれば、Planの段階で修正を依頼します。内容に納得するまでAgentへ切り替えません。

### 既存構成から Bicep のたたき台を作る

1. 計画を確認できたらAgentに切り替え、メモしたリソース情報から Bicep のたたき台を作ってもらいます。
    - 次の Azure リソース一覧をもとに、Bicep のたたき台を作成してください。
    - まずはデプロイしない前提で、読みやすさを優先してください。
    - 既存リソース参照と新規作成リソースを分けてください。
    - VM、NIC、Subnet、NSG、NAT Gateway の関係を Bicep で表現するサンプルを作成してください。
1. Agentが提示したファイル差分を開き、計画にないファイルやシークレットが含まれていないことを確認してから採用します。チャット回答としてコードが返された場合は、`main.bicep` などの新しいファイルに貼り付けます。
1. Copilot Chat にレビューを依頼します。
    - この Bicep はどの Azure リソースを作成または参照しますか？
    - 実運用に入れる前に直すべき点を指摘してください。
    - パスワード、SSH キー、トークンなどのシークレットを安全に扱う方法を提案してください。
    - この Bicep はデプロイせず、build だけで確認する前提です。危険な点があれば教えてください。

### Bicep をビルドして構文確認する

実際の Azure デプロイは行いません。Bicep の build は、プログラミング言語でいうコンパイルに近い確認です。Bicep ファイルを ARM テンプレートに変換できるか、構文エラーがないかを確認します。

リポジトリにファイルを生成したくない場合は、`--stdout` を付けて実行します。

```bash
az bicep build --file ./main.bicep --stdout
```

`az deployment group create` は実デプロイになるため、このハンズオンでは実行しません。Jenkins などのデプロイ設定ファイルも今回の範囲外です。

ビルドに失敗した場合は、ProblemsパネルまたはターミナルのエラーをCopilot Chatへ追加し、原因と最小限の修正を依頼します。修正後は同じbuildコマンドを再実行します。

## プロンプト例

- Azure Portal で手動作成した VM を Bicep 化するとき、どの情報を控えておく必要がありますか？
- この Bicep の命名規則を改善するなら、どのようなルールにできますか？
- `existing` キーワードはどのようなときに使いますか？
- VM の管理者パスワードを Bicep に直接書かないためにはどうすれば良いですか？
- 本番環境向けにするなら、どのパラメーターを外出しすべきですか？
- `az bicep build` と `az deployment group create` の違いを説明してください。

## 余裕がある方向けの追加ワーク

1. 作成した Bicep を、ネットワーク、VM、パラメーターの観点でモジュール化する案を Copilot に相談します。
1. 作成した Bicep の README を作り、build 手順と注意点をまとめます。
1. Bicep ではなく Terraform で書く場合の構成案を比較してもらいます。
