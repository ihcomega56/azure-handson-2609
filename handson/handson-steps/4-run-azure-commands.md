## この章でやること

自然言語で Azure の確認作業を依頼し、AI が Azure CLI を実行する体験をします。

目安時間: 15分

## 手順

### 自然言語で Azure の確認作業を依頼する

1. GitHub Copilot CLI または VS Code の Agent Mode を使い、自然言語で Azure の確認作業を依頼します。
1. 最初は読み取り専用の確認作業だけを依頼します。
    - 対象リソースグループにある VM の一覧を表示してください。
    - VNet、Subnet、NSG、NAT Gateway の関係を説明してください。
    - GitLab VM に Public IP が紐づいているか確認してください。
1. AI が実行しようとしているコマンドが表示されたら、次のどちらかに分類してから承認します。
    - 読み取り専用: `show`、`list`、`what-if` など
    - 変更を伴う: `create`、`update`、`delete`、`apply` など
1. 分類に自信がない場合は、実行前に「このコマンドはAzureリソースを変更しますか」とCopilotへ確認します。この章では読み取り専用コマンドだけを承認します。
1. 実行結果を Copilot に説明してもらいます。
    - 取得結果を表にしてください。
    - この結果から分かることを初心者向けに説明してください。
    - 次に確認すべき観点を提案してください。

手順中のサンプル名は、自分のチームのリソース名に読み替えてください。

## プロンプト例

- Azure CLI を使って、対象リソースグループ内の VM 名、サイズ、プライベート IP、パブリック IP を確認してください。
- VNet に含まれるサブネットと NSG の関連付けを確認してください。結果は表にしてください。
- Azure Bastion 経由で VM に接続するために確認すべき情報を取得してください。
- これから実行しようとしているコマンドが、リソースを変更しない読み取り専用操作か確認してください。

## 余裕がある方向けの追加ワーク

1. 変更を伴うプロンプトの例を確認します。Azure リソースを変更する操作なので、実行はしません。
   - VM に対して、既存の公開 IP を削除して、別の IP を関連付けてください。
   - このリソースグループに新しい VM を作成し、OS の設定と管理者ユーザーを指定してください。
   - この NSG にルールを追加して、ポート 8080 を開放してください。
